# 0917 進度摘要（家用電腦，feature/social 分支）

## 背景
公司電腦的 Claude Code session 斷線（電腦沒開機），改在家用電腦接續。這台電腦原本沒裝 Node.js，已用 winget 安裝 Node.js LTS 並 npm install 完成 QMAH.Client 依賴。

## 這次要解的問題
現有前端（9/16 已 commit 並推上 origin/feature/social，涵蓋貼文/留言/活動/公告/後台管理四頁）有個「切換頁面時讀不到資料」的 bug：API 明明有回傳資料，畫面卻卡住不更新（通常是一直轉圈圈）。

## 根因
這個開發環境下 zone.js 沒有 patch 到 XMLHttpRequest，導致 HttpClient 的回應完全不會觸發 Angular 變更偵測——元件狀態其實已經正確更新（用 `ng.getComponent()` 檢查過 `posts.length` 等欄位都對），但 DOM 不會重新渲染。

原本 app.config.ts 裡有個 `forceRefreshAfterApiCallInterceptor`，想用手動 `ApplicationRef.tick()` 補救，但這個 tick() 常常因為 NavBar 的通知鈴鐺輪詢等因素丟出 `NG0100 ExpressionChangedAfterItHasBeenCheckedError`，一旦拋出就會讓整輪 tick 半路中斷，導致後面的元件（例如主要內容區）永遠沒被檢查到。

## 修法
1. 移除 app.config.ts 裡的 `forceRefreshAfterApiCallInterceptor`（含 `ApplicationRef.tick()` 那段）。也試過改用 `NgZone.run()` 包一層，但同樣沒用（NgZone 的 stable 機制看起來也沒被正確觸發）。
2. 改成在每個會非同步抓資料的元件裡注入 `ChangeDetectorRef`，在 subscribe 的 next/error callback 裡手動呼叫 `this.cdr.detectChanges()`。這個做法已實測有效。

已套用到以下 9 個元件（每個檔案的 next/error callback 都加了 detectChanges）：
- src/app/features/social/posts/posts.ts
- src/app/features/social/post-detail/post-detail.ts
- src/app/features/social/events/events.ts
- src/app/features/social/event-detail/event-detail.ts
- src/app/features/social/announcements/announcements.ts
- src/app/features/admin/admin-events/admin-events.ts
- src/app/features/admin/admin-reports/admin-reports.ts
- src/app/features/admin/admin-posts/admin-posts.ts
- src/app/features/admin/admin-comments/admin-comments.ts

app.config.ts 現在只剩 `apiCredentialsInterceptor`（處理 withCredentials），沒有其他攔截器。
